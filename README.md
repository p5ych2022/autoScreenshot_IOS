# autoScreenshot：手机截图自动裁剪可行性原型

## 结论与当前状态

这是电脑上已运行的 Python + Pillow 原型，不是已经部署到 iPhone 的成品。

- 对 `sample/` 中 4 张截图使用同一套算法，不按文件名、App 名称或每张图的固定坐标裁剪。
- 根据外围近黑/近白背景与连续内容区域定位候选矩形；允许外围出现少量状态栏文字和按钮。
- 在小图上分析，在完整输入截图上执行裁剪，输出新的 PNG 文件；不修改或删除原始文件。
- 不使用网络接口、服务器、OpenCV、NumPy 或大模型。
- Pythonista 输入/输出桥接代码已写入，但只做过模拟接口测试，尚未经过 iPhone 实机验证。
- 输出是候选裁剪框，不是经校准的置信度；即使标为 `candidate`，也可能误判。

## 查看效果

- `results/comparison.jpg`：四张样本的检测框与裁剪结果总览。
- `results/index.html`：可用本地浏览器打开的详细对照页。
- `results/*.cropped.png`：新生成的裁剪图片。
- `results/*.marked.png`：原始画面加绿色检测框，仅供核验。
- `results/results.json`：裁剪坐标、尺寸、耗时和原文件完整性检查。

实验输出中的检测框图片仅用于开发核验，手机端流程不生成这些调试图片。

## 本次实验记录

环境：macOS、Python 3.14.7、Pillow 12.2.0。
坐标为 `(left, top, right, bottom)`，右/下边界不包含在输出中。

| 55 | 1125 × 2436 | (0, 488, 1125, 2034) | 1125 × 1546 | 0.404 秒 |

耗时包括解码、检测和内存裁剪，不包括结果编码/写盘、快捷指令启动或照片入库；不是 iPhone 性能数据。

人工查看结果：4 张主体区域基本保留，外围工具栏/评论区被裁掉。为避免吞掉内容，边界向外保留一个分析像素，映射回原图后可能留下数个像素的边框或界面碎片。55 号样本底部仍可能看到少量轮播点；不应把结果描述成像素级完美裁边。

54 号样本右下角原有水印仍在；裁剪不会修复图片内部水印、字幕、遮挡或屏幕之外的内容。

4 张原始文件处理前后的 SHA-256 均一致。输出 PNG 不再次使用 JPEG 有损编码，但无法恢复输入 JPEG 已损失的质量，文件体积也可能比原 JPEG 大。

## 运行方式

电脑需要 Python 3.10+ 和 Pillow。`requirements.txt` 固定的是本次电脑验证版本；不要把它当作 Pythonista 的安装清单。

从项目目录运行：

```sh
python3 crop_screenshot.py sample --output results_new
python3 -m unittest -v
```

输出目录必须不存在或为空，防止覆盖已有成果。已有的 `results/` 保留本次实验输出。

## 测试范围

16 个测试方法通过，包括：

- 黑边、白边、近黑/近白、四边与仅上下/左右留边；
- 横向画布、工具栏小图标、图内局部暗色/白色区域；
- 空白图/无边框图不强制裁剪，多块较大内容区域返回待检查；
- JPEG 压缩、极小图片；
- 合成样本 0.5/1/2/4 倍尺寸，以及真实样本 0.5/1.5 倍缩放；
- 原始文件不改动；Pythonista 图片输出接口模拟与失败时停止输出。

这些是回归/合成测试，不是通用准确率，也不是手机实机验收。
样本的两种分辨率宽高比几乎一致，不能证明不同手机、字体缩放、横竖屏切换、App 新版本均能正确处理。

## Pythonista 对接方案：待实机验证

先把 `crop_screenshot.py` 导入 Pythonista 本地脚本库。首次测试建议增加预览，不直接无提示保存。

建议快捷指令动作：

1. “截屏”，将结果作为后续步骤的输入，不先存入相册。
2. “Run Pythonista Script”，选择此脚本。
3. 将截图放入动作的 `Input Files`，而不是当作文本填入 `Arguments`；只传一张图。
4. 关闭 `Run in Pythonista`，在快捷指令扩展里运行；可关闭 `Show When Run`。
5. 将返回图片交给“快速查看”供首次验证，再交给“存储到相簿”。
6. 验证无误后，在“设置 → 无障碍 → 触控 → 轻点背面”绑定整个快捷指令。

脚本用 `shortcuts.set_output_image()` 返回 PIL 图片，不直接访问相册，不查找“最新照片”，不删除任何照片。后台模式不能由脚本随意弹出交互界面；当前原型定位失败时抛出错误，阻止继续自动保存。完整的失败预览/人工选择流程尚未实现。

需要实机验证：当前画面是否被正确截取、是否不切换 App、目标设备上的内存限制、耗时、权限提示及照片入库行为。电脑侧通过不代表这些已经通过。

## 算法限制与后续样本

- 依赖同一轴两侧均存在相近的近黑/近白背景；单边留白、两侧颜色不同、彩色或渐变界面可能不识别。
- 多图信息流、边缘同色海报、暗色主体延伸到边框、内容与界面没有明显边界时可能误判。
- 稀疏的白底文字图可能被当成界面；连续深色区域也可能造成不完整候选框。
- 本原型不进行 App 识别、不做 OCR、不修复遮挡，也没有模型意义上的语义理解。
- 还需补充真实白色界面、不同宽高比设备、系统原始 PNG、复杂布局和无边框反例。

优先提高边界精度和错误兜底，再决定是否需要 App 页面规则。当前无需服务器。
