# autoScreenshot：手机截图自动裁剪可行性原型

## 结论与当前状态

这是电脑上已运行的 Python + Pillow 原型，不是已经部署到 iPhone 的成品。

- 对 `sample/` 中 4 张截图使用同一套算法，不按文件名、App 名称或每张图的固定坐标裁剪。
- 根据外围近黑/近白背景与连续内容区域定位候选矩形；允许外围出现少量状态栏文字和按钮。
- 在小图上分析，在完整输入截图上执行裁剪，输出新的 PNG 文件；不修改或删除原始文件。
- 不使用网络接口、服务器、OpenCV、NumPy 或大模型。
- Pythonista 输入/输出桥接代码已写入，但只做过模拟接口测试，尚未经过 iPhone 实机验证。
- 输出是候选裁剪框，不是经校准的置信度；即使标为 `candidate`，也可能误判。

## 查看效果

- `results/comparison.jpg`：四张样本的检测框与裁剪结果总览。
- `results/index.html`：可用本地浏览器打开的详细对照页。
- `results/*.cropped.png`：新生成的裁剪图片。
- `results/*.marked.png`：原始画面加绿色检测框，仅供核验。
- `results/results.json`：裁剪坐标、尺寸、耗时和原文件完整性检查。

实验输出中的检测框图片仅用于开发核验，手机端流程不生成这些调试图片。

## 运行方式

电脑需要 Python 3.10+ 和 Pillow。`requirements.txt` 固定的是本次电脑验证版本；不要把它当作 Pythonista 的安装清单。

从项目目录运行：

```sh
python3 crop_screenshot.py sample --output results_new
python3 -m unittest -v
```

输出目录必须不存在或为空，防止覆盖已有成果。首次实验输出使用 `results/`；如果已清理，可选择新的输出目录重新生成。

## Pythonista 手机安装与联调：待实机验证

先验证“选择一张截图 → 裁剪 → 预览”，成功后再启用背面轻点。无需服务器，也无需在手机安装 `requirements.txt`；Pythonista 已内置 Pillow。

### 1. 导入脚本

只需要 `crop_screenshot.py`，不必传整个项目或结果目录。

1. 在 Mac 的 Finder 中找到 `/Users/psych/Code/autoScreenshot/crop_screenshot.py`。
2. 将文件复制到同一 Apple 账户的 iCloud Drive，等待手机“文件”App 能看到它。也可以用自己的文件传输方式先将文件存入手机“文件”App。
3. 打开 Pythonista，进入本地脚本列表，点击“+”→“Import…”，从系统文件选择器选中该文件。
4. 确认本地脚本列表中有 `crop_screenshot.py`。

后续电脑代码更新后，需要重新导入对应文件。`2026-09-23.3` 起支持两种入口：快捷指令后台运行处理 `Input Files`；Pythonista 主 App 直接运行则进行本地文件裁剪预览。

### 直接在 Pythonista 中运行：先验证本地裁剪

1. 将新版 `crop_screenshot.py` 与 `IMG_2844.PNG` 放在 Pythonista 内的同一个目录，名称应完全一致。不要只把图片放在“文件”App 的另一个目录。
2. 在 Pythonista 编辑器打开脚本，直接点击运行三角形，无需快捷指令。
3. 没有启动参数时默认处理同目录 `IMG_2844.PNG`；如需处理其他文件，可使用 Pythonista 的脚本启动参数传入一个图片路径，相对路径按脚本目录解析。
4. 控制台应出现“本地预览模式 2026-09-23.3”、输入尺寸、检测状态、裁剪框、输出尺寸以及保存路径。
5. 找到候选框后会生成 `IMG_2844.cropped.png`，随后弹出图片预览。重复运行会创建 `IMG_2844.cropped-2.png` 等新文件，不覆盖旧结果。
6. 原始图片不会被修改或删除，结果保存在脚本/图片所在目录，不会自动进入系统照片相册。无法可靠定位时只打印原因，不生成新图。

这是主 App 的本地模式，不依赖快捷指令的图片输出接口；成功也不能证明后台扩展内存和快捷指令传图问题已解决。如果预览失败但控制台显示已保存，可以从脚本目录手动打开新生成的 PNG。

仍使用 `pythonista_diagnostic.log` 记录阶段，本地运行开头为 `LOCAL_START`。运行会覆盖上一次日志，如要排查此前快捷指令空白，请先保留此前日志。

### “Script Output 为空白”与本地预览的区别

`Script Output` 是快捷指令动作输出的名称，不是保存到相册的图片文件名。执行未报错不等于图像已经正确传给“快速查看”，目前空白原因尚未确定。

- 快捷指令正常图像模式：`Arguments` 留空，输出应为裁剪图；`Run in Pythonista` 关闭，“快速查看”绑定 Pythonista 动作的输出，`Show When Run` 可关闭。
- `Arguments=diagnose`：仅输出检测文字报告，不返回图片。
- 主 App 本地模式：只写本地 PNG 并预览，不直接返回图片给快捷指令。因此不要把打开 `Run in Pythonista` 当作修复空白的办法。
- 若快捷指令仍为空白，保留动作设置截图和日志末尾，检查是否到达 `OUTPUT_DONE`；即便到达也只是输出函数返回，不代表系统后续传输或预览成功。

### 2. 建立不保存图片的测试快捷指令

打开“快捷指令”，新建指令，命名为“自动裁图测试”，按顺序添加三个动作。

**动作一：“选择照片”**

- 关闭“选择多张”，仅传入一张图片。
- 首次选此前提供的、尚未裁剪且黑边明显的截图，不选已经裁好的结果。

**动作二：Pythonista 的“Run Pythonista Script”**

搜索“Pythonista”找到该动作，不选旧的“Run Script / Edit Script”或分享菜单里的同名入口。部分选项需要展开动作才能看到。

| 选项 | 设置 |
|---|---|
| Script | 选择本地 `crop_screenshot.py` |
| Inline Script | 若显示该开关，关闭，使用文件脚本 |
| Arguments | 留空，不填文件路径或图片 |
| Input Files | 选择动作一“选择照片”的输出变量，不手工输入文字 |
| Run in Pythonista | 关闭，这是直接返回图片给快捷指令的必要条件 |
| Show When Run | 关闭，预览交给下一动作 |

**动作三：“快速查看”**

将输入明确设为动作二“Run Pythonista Script”的输出，而不是动作一的照片。

运行测试并选择一张原始截图。预期看到裁剪结果，无需跳进 Pythonista 主 App。此阶段不添加“存储到相簿”，不会新增照片，也不会删除已存在的原始照片。首次运行按系统提示授予所需访问权限。

### 3. 改为实时截屏，绑定背面轻点

测试成功后，把指令重命名为“自动裁图”：

1. 删除“选择照片”，在首位添加“截屏”（Take Screenshot）。
2. 重新设置 Pythonista 动作的 `Input Files`，指向新“截屏”动作的输出；删除旧动作后变量可能失效。
3. 暂时保留末尾“快速查看”，先验证实时截到的是目标 App 的画面。
4. 进入“设置 → 无障碍 → 触控 → 轻点背面 → 轻点两下”，在快捷指令列表选择“自动裁图”，不要选择系统自带的“截屏”。
5. 返回目标 App，打开带明显留边的图片，轻点背面两下，检查裁剪预览。

不要在快捷指令编辑界面运行来检验目标 App 截图，否则截到的可能就是快捷指令界面。

### 4. 开启只保存裁剪结果

实时预览通过后，删除“快速查看”，添加“存储到相簿”（Save to Photo Album）：

- 输入明确选择 Pythonista 动作的输出；不要选最前面的“截屏”变量。
- 选择要保存的相册，也可使用默认相册。
- 可在最后添加“显示通知：裁剪图片已保存”。

最终链路为：截屏 → Run Pythonista Script → 存储到相簿。

原始截图不先写入图库，只有裁剪结果入库，因此无需删除原图。已有相册照片不会被改动；前面的选图测试也不会删除其原始照片。

### “一张通信错误、四张出现脚本校验错误”的诊断

这个现象说明脚本在四张输入时已启动，但在读取图像前停止，不能据此证明图像处理或输出接口正常。单张图会继续进入解码、检测、裁剪、返回图片；内存峰值或原生接口错误是待验证原因，不是已确认结论。

`2026-09-23.2` 版减少了不必要的原尺寸图像拷贝，并在返回裁剪图之前释放原图。输出仍按原始截图分辨率裁剪，不用降低最终画质换取成功。

1. 将电脑更新后的 `crop_screenshot.py` 重新导入 Pythonista，替换旧文件，并在快捷指令中重新选中更新后的脚本。电脑修改不会自动更新已经导入手机本地的副本。
2. 保持一次选择一张图、`Arguments` 留空、`Run in Pythonista` 关闭，先用原测试流程重试；不要添加保存或删除动作。
3. 若仍失败，在 Pythonista 的脚本同目录找到 `pythonista_diagnostic.log`。打开后提供内容，尤其是最后几行及开头的版本标记。日志每次运行覆盖，只记录阶段、尺寸、格式、错误类型，不记录图片内容。
4. 找不到日志时，先检查是否导入了新版且选择了正确脚本。如果脚本目录不可写，日志改为输出到控制台，可尝试开启 `Show When Run`；进程被系统终止时不保证能看到控制台内容。

日志中的最后阶段帮助缩小范围：

| 最后一项 | 排查范围 |
|---|---|
| `HEADER_BEGIN` | 文件格式识别或读取文件头 |
| `DECODE_BEGIN` | 图片解码、颜色转换或 EXIF 处理 |
| `DETECT_BEGIN` | 分析缩略图和边界检测 |
| `CROP_BEGIN` | 创建原分辨率裁剪图 |
| `OUTPUT_BEGIN` | Pythonista 将图片交给快捷指令的接口 |
| `OUTPUT_DONE` | 图片输出函数已返回，但不保证系统后续传输/预览成功 |
| `ERROR` | 捕获到 Python 异常，应同时查看系统展示的详细错误 |

还可以只验证检测阶段：将 **Arguments 设置为纯文本 `diagnose`**，仍通过 **Input Files** 传同一张图。末尾保留“快速查看”，它这次显示文字报告，不是图片；不要连接“存储到相簿”。报告成功说明解码/检测和文字输出走通，不代表裁剪及图片输出已通过。检测结果可以是 `candidate` 或 `review`。诊断结束后清空 `Arguments` 恢复图片输出模式。

若需对比尺寸影响，可在诊断副本中、Pythonista 前增加“调整图像大小”，宽度设为 600、高度自动，并将缩图输出绑定到 `Input Files`。这仅用于排查，不作为正式降低分辨率的解决方案；小图能成功支持问题与负载/格式有关，但单独这一结果不能证明一定是内存原因。

### 常见问题

| 现象 | 优先检查 |
|---|---|
| 搜不到 Pythonista 动作 | 先打开 Pythonista 完成首次启动，再重新打开快捷指令搜索 |
| 脚本选择器找不到文件 | 确认通过 Import 导入了 Pythonista 本地脚本库，而不是仅放在“文件”App |
| `Pass exactly one screenshot using Input Files` | `Input Files` 是否绑定图片输出、是否仅选一张；`Arguments` 应为空 |
| 提示必须从 Shortcuts 启动，或跳入 Pythonista | 旧版直接运行会报提示，请更新到 `.3`；快捷指令传图模式仍需关闭 `Run in Pythonista`，编辑器直接运行则为本地预览 |
| `Cannot safely locate a single image` | 当前图片没有找到可靠候选框；换先前黑边明显的样本，不要理解为 Pythonista 未安装成功 |
| 预览仍是原图 | “快速查看”是否错误绑定了“选择照片”或“截屏”的输出 |
| 进程终止、无结果或内存错误 | 保留错误截图与输入图片尺寸，需排查扩展内存限制；不要直接开启主 App 模式绕过，现有返回接口不适用于该模式 |

脚本用 `shortcuts.set_output_image()` 返回 PIL 图片，不直接访问相册，不查找“最新照片”，不删除任何照片。后台模式不能由脚本随意弹出交互界面；当前原型定位失败时抛出错误，阻止继续自动保存。完整的失败预览/人工选择流程尚未实现。

以上是配置步骤，不代表已经实机验证成功。待验证项：机型/iOS 版本、当前画面截取、不切换 App、扩展内存、耗时、权限提示和最终照片入库行为。

## 算法限制与后续样本

- 依赖同一轴两侧均存在相近的近黑/近白背景；单边留白、两侧颜色不同、彩色或渐变界面可能不识别。
- 多图信息流、边缘同色海报、暗色主体延伸到边框、内容与界面没有明显边界时可能误判。
- 稀疏的白底文字图可能被当成界面；连续深色区域也可能造成不完整候选框。
- 本原型不进行 App 识别、不做 OCR、不修复遮挡，也没有模型意义上的语义理解。
- 还需补充真实白色界面、不同宽高比设备、系统原始 PNG、复杂布局和无边框反例。

优先提高边界精度和错误兜底，再决定是否需要 App 页面规则。当前无需服务器。
